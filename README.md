# 文旅行业情报 Agent

一个本地运行的 Streamlit 网页，按研究主题抓取真实新闻，
默认使用 OpenAI 提炼带证据的量化案例，也可切换到 Gemini，
分析结果写入 SQLite 新闻/案例数据库。

## Streamlit Community Cloud 快速展示

如果需要一个别人点开即可查看的 `*.streamlit.app` 网址，请按
[STREAMLIT_CLOUD.md](STREAMLIT_CLOUD.md) 操作。

Cloud 展示版无需登录，每个浏览器会话拥有独立的搜索记录、新闻和案例。
访客只能查看、审核和导出本次会话的结果；网页不再提供全站管理或主题修改入口。

## 第一版功能

- 首次启动时从项目内的《复星旅文 DeepResearch 研究主题目录》导入 28 个主题。
- 按主题手动搜索 Google News / Bing News RSS，输出真实原文链接。
- 提取新闻正文，记录媒体来源、发布时间和正文指纹。
- OpenAI/Gemini 输出摘要、量化案例、证据原文、企业、地区、指标标签和相关性。
- 低分结果保留在「新闻池」；达到门槛且有量化内容的结果进入「案例库」。
- 同一主题按 URL 和正文 SHA-256 指纹去重。
- 案例可标记为待审核、已确认或已忽略，并可导出 Excel。
- 「我的记录」展示本次会话的搜索历史，可以重新打开已完成的结果。
- 独立 worker 可按配置的主题周期采集，使用独立于网页会话的数据库。

## 环境准备

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
cp .env.example .env
```

打开 `.env`，填写 OpenAI 配置：

```env
AI_PROVIDER=openai
OPENAI_API_KEY=你的_OpenAI_API_Key
OPENAI_MODEL=gpt-5.6-luna
```

如需继续使用 Gemini，把 `AI_PROVIDER` 改为 `gemini`，并填写
`GEMINI_API_KEY` 和 `GEMINI_MODEL`。
不要将 `.env` 提交或发送给其他人。

## 启动网页

```bash
source .venv/bin/activate
streamlit run app.py
```

网页为每个浏览器会话创建独立的临时 SQLite 数据库。刷新、新开标签页或
重新打开页面可能开始新会话，重要结果请及时导出；没有账号或跨设备历史同步。
会话释放且后台任务结束后，临时存储会清理。

独立 worker / 命令行流程仍使用 `DATABASE_PATH`（默认 `data/industry_news.db`），
已有数据保留，但不会展示给网页访客。原始研究主题 Excel 只会读取，不会被网页改动。

## 启动周期采集

在第二个终端中执行：

```bash
cd "/Users/mr.jiang/Desktop/新闻数据爬取网页"
source .venv/bin/activate
python3 worker.py
```

worker 默认每 30 分钟检查一次到期主题：

- 每轮默认最多处理 2 个主题，避免集中消耗 AI API 配额。
- worker 启动后不立即抓取，会在第一个扫描周期到达时开始。
- 「实时」和「事件驱动」主题：默认每 4 小时采集。
- 其他主题：默认每 24 小时采集。

报告频率仍保留 Excel 中的实时、周报、月报、季度等业务定义，
与底层新闻采集间隔分开管理。

> worker 是本地进程。终端关闭或电脑关机后不会继续采集。

## 页面说明

- 网页默认显示英文，右上角点击 **中/ENG** 可一键切换搜索页和「我的记录」的界面语言。
- 语言选择保存在当前会话及网址的 `lang` 参数中；刷新当前网址会保留选择。
- 切换语言会保留当前搜索输入、筛选条件和已生成的评分结果，不重新调用 AI。新闻原文、已有 AI 摘要和自定义研究主题保留原始语言。
- 搜索意图确认页的摘要、澄清问题、选项和说明由 AI 一次生成中英文版本；切换时保留已选方向和补充输入。AI 返回缺失的英文文案会触发一次重试，仍失败时使用双语备用方案。
- 页脚署名为 **Zibo Jiang · Fosun**。
- 高质量结果表的界面列名及 Excel/CSV 导出列名随语言切换；切换时保留当前表格编辑和导出勾选。

- **新闻搜索**：首页主流程，AI 先识别关键词范围与歧义；用户确认后，搜索、预筛和正文分析进入后台任务，切换「我的记录」不会中断。
- **我的新闻**：首页下方展示本次会话已分析的新闻，包含低分结果。
- **我的案例**：展示本次会话达到门槛的量化案例，支持筛选和 Excel 导出。
- **我的记录**：右上角的文字按钮替代原来的小齿轮；查看本次会话的关键词、任务状态、新闻和案例，并审核自己的案例。
- 搜索任务仅属于发起任务的会话，不通过网址恢复；复制网址给别人不会共享搜索记录。

## 搜索意图确认

手动搜索采用“先确认、后搜索”的两步流程：

1. AI 判断输入范围是宽泛、适中还是具体，并识别可能的语义歧义。
2. 范围过大或存在歧义时，页面直接展示 4 个边界清晰的细分方向；用户可以单选、多选，或直接输入自己真正想搜索的内容。
3. 选择预设方向后，系统交错合并各方向的中英文检索词；填写自定义内容时则直接按自定义目标生成检索词并开始搜索，不再增加一次往返确认。新闻命中任一已选方向即可视为相关，不要求同时覆盖全部方向。
4. “每个检索方向的文章数量”会按已选方向数扩大共享结果池。例如每个方向 8 篇、选择 3 个方向，本次最多处理 24 篇；单次上限为 40 篇。相关性筛选后，不保证每个方向最终正好返回相同数量。
5. 用户确认后，系统才访问新闻源，后续搜索相关性评分始终以用户确认过的一个或多个目标为准。

定时 worker 无法实时询问用户，仍直接使用其数据库中已配置的主题和检索词。

### 意图确认的等待时间

- 意图识别使用 `INTENT_TIMEOUT_SECONDS`（默认 20 秒，允许 5–60 秒）的请求时间预算，关闭 SDK 自动重试；超时、限流和认证失败直接返回双语备用方案。只有格式或翻译不完整会在剩余预算内再试一次。
- 硅基流动 DeepSeek V4 和 DeepSeek 官方接口的意图请求关闭思考模式，输出采用简短的双语说明，并限制输出长度。新闻评分和正文分析的设置独立于此步骤。
- 同一浏览器会话内，相同关键词和模型配置的成功意图方案缓存 15 分钟（最多 12 条）；失败的备用方案不会缓存，重试可重新请求 AI。新闻结果不会因该缓存而跳过抓取。
- 可设置 `INTENT_MODEL`，为意图识别单独指定同一 API 提供方的模型；不填写则沿用主模型。硅基流动可按账号的可用模型列表设置，例如 `deepseek-ai/DeepSeek-V4-Flash`。
- 本地在 `.env` 配置，Cloud 在 Streamlit Secrets 配置。等待时显示已用时间，日志记录意图请求耗时，便于区分模型慢与网络异常。

## 新闻质量评分

系统将“搜索相关性”和“新闻质量”分开显示：相关性回答“是否符合本次搜索”，新闻质量回答“报道本身是否可靠、完整、可核验”。新闻质量严格按 100 分计算，时效性只占 5 分，避免年度报告和深度研究被过度降分。

### 评分维度

| 维度 | 满分 | 计算方式 |
|------|------|----------|
| 来源权威度 | 25 | AI 结合原始发布者、官网、编辑/研究标准和一手资料属性评分 |
| 正文信息密度 | 10 | 文章长度 + 段落结构 |
| 数据含量 | 10 | 含数字/百分比句子的占比 |
| 时效性 | 5 | 2 个月内 5 分，4/6/9/12 个月内依次 4/3/2/1 分，超过 1 年 0 分 |
| 正文证据与可核验性 | 15 | AI 判断关键事实、数据和结论是否有正文内证据支撑 |
| 报道完整性 | 10 | AI 判断事件、背景、主体、影响和必要上下文是否完整 |
| 信源与方法透明度 | 10 | AI 判断具名信源、引用、数据口径和研究方法是否透明 |
| 标题正文一致性 | 5 | AI 判断标题是否准确反映正文且不夸大 |
| 客观与平衡性 | 5 | AI 判断是否区分事实与观点，并说明必要的局限或风险 |
| 清晰与连贯性 | 5 | AI 判断结构、逻辑和表达是否清晰准确 |
| 扣分项 | 独立 | 煽动性标题、正文过短、缺乏支持的断言 |

新闻卡片出现后，系统会先并行调用 AI 评估搜索相关性与来源权威度，再结合信息密度、数据含量和时效性生成满分 50 分的“基础分”；随后仅对相关性达到 60 分的文章进行第二段 AI 正文分析，补齐 50 分正文质量，形成满分 100 分的综合质量分。搜索相关性独立展示，不混入新闻质量分。

### 高质量门槛

- 综合质量达到 85 分，且来源权威度不少于 15/25、AI 正文质量不少于 35/50，才标记为“高质量”。
- 正文提取不足 300 字、存在严重无支持断言或标题与正文严重不一致时，综合分封顶 59 分，并明确提示“可能提取不完整”或对应原因。
- 来源权威度或 AI 正文质量未达到上述最低门槛时，综合分封顶 84 分。

### 质量等级

| 分数范围 | 等级 | 含义 |
|----------|------|------|
| 85-100 | 🟢 高质量 | 来源可靠、正文证据充分，达到高质量新闻标准 |
| 75-84 | 🔵 质量良好 | 报道整体可靠，但仍有部分维度可以补强 |
| 60-74 | 🟡 一般 | 报道质量一般，部分维度存在不足 |
| 40-59 | 🟠 偏低 | 报道质量偏低，建议交叉验证 |
| 0-39 | 🔴 较低 | 报道质量较低，信息不足或来源不明 |

> 质量评分衡量的是报道本身的完整性和可信度，不代表对新闻真实性的最终判定。

### 评分缓存

相同文章正文（通过 SHA-256 哈希）在评分规则不变时不重复评分。
新闻质量规则版本为 `v9`，搜索相关性规则版本为 `r2`；后续规则变更时会自动触发重新评分。

## 搜索结果排序

新闻池和案例库支持四种排序方式：

- **最新发布**：按发布时间从新到旧（默认）
- **最早发布**：按发布时间从旧到新
- **质量最高**：按报道质量评分从高到低
- **质量最低**：按报道质量评分从低到高

缺少发布时间的文章默认排在最后。


## 本地测试

Windows PowerShell 可使用项目内的独立环境：

```powershell
python -m venv .venv-win
.\.venv-win\Scripts\python.exe -m pip install -r requirements.txt
.\.venv-win\Scripts\python.exe -m streamlit run app.py
```

`.venv-win/`、`__MACOSX/` 和 `._*` 已加入 `.gitignore`，不纳入版本管理。

Windows 运行自动测试：

```powershell
.\.venv-win\Scripts\python.exe -m unittest discover -s tests -v
```

macOS / Linux 激活虚拟环境后运行：

```bash
python3 -m unittest discover -s tests -v
```

测试使用临时 SQLite 数据库，不请求新闻站点，也不调用真实 AI API。

## 当前边界

- 仅处理公开可访问页面，不绕过登录、付费墙或反爬验证。
- JavaScript 渲染页面可能无法提取正文。
- Agent 输出必须经人工审核，特别是金额、比例和人事信息。
- 第一版不自动生成周报/月报正文，只完成连续采集与案例积累。
